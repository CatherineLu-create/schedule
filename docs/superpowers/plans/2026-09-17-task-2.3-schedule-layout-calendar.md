# Schedule Layout and Calendar Input Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the one directly rendered Schedule below Resources and make the browser's native calendar the primary Draft Plan/Actual editor, with immediate canonical updates and explicit Clear.

**Architecture:** Keep `App`'s mounted `PrototypeState` reducer and the existing Schedule commands, selectors, and callback bridge. Slice 1 moves one JSX instance in `ProjectWorkspace`; Slice 2 replaces only `DateOnlyEditor`'s text interaction with an enabled native date input, an Open calendar trigger, explicit Clear, and transient unapplied feedback. No second Schedule authority or new data model is introduced.

**Tech Stack:** React, TypeScript, Vite, Vitest, Testing Library, native HTML `<input type="date">` and `showPicker()`.

**Spec:** `docs/superpowers/specs/2026-09-17-task-2.3-schedule-layout-calendar-design.md` (approved layout/calendar addendum). Read its referenced `2026-09-17-task-2.3-human-acceptance-corrections-design.md` and `2026-09-11-task-2.3-schedule-working-draft-publish-lifecycle-design.md` only for preserved contracts.

## Global Constraints

- Project Workspace order is Project Master, Resources, one directly rendered Schedule Workspace, then existing feedback/content. The Schedule resource says `Shown below` and has no `Open Schedule` action.
- Draft Plan and Actual use small, enabled native date controls. Their adjacent accessible Open calendar buttons call `showPicker()` synchronously in the click handler when supported; otherwise focus the input and retain its native affordance. If the target Windows browser lacks a usable mouse-operated native picker, stop for a human product decision.
- A complete native `YYYY-MM-DD` value must pass unchanged through `parseDateOnly()` and the existing `onUpdateMilestone` callback as `DateOnly`; explicit Clear alone sends `null`. Never send `null` for an empty native input event, picker opening, month/year movement, or cancellation. Do not use `Date`, `valueAsDate`, `valueAsNumber`, timezone conversion, or a slash-text adapter.
- Preserve visible and accessible `Date not applied` feedback for incomplete, invalid, or command-rejected input, and the existing Publish presentation guard until canonical props reflect a valid selection or explicit Clear. No new Publish business-completeness rule.
- Keep `PrototypeState.schedules` the sole embedded zero-or-one Draft authority by exact ProjectId. Accepted Draft edits survive Dashboard/Project navigation within the mounted app; Current Schedule and Portfolio remain Current Published-only. Preserve immutable max+1 Publish, Discard, malformed Draft recovery, confirmation reset, legal no-Published state, Dashboard `N/A`, A/A2, and catalog authority.
- Team Member, Weekly Report, and AVL remain disabled with `Migration pending`. No dependency, custom calendar, Save Draft, storage, backend, parser, fixture, timeout, or test-configuration work. Historical specs and corrective A-D plan stay unchanged. Task 2.3 remains open pending human UI acceptance.
- For later implementation verification, use `VITEST_MAX_WORKERS=2` explicitly for the full suite. Historical qualification: 47 files / 554 tests passed with that override; default-worker runs timed out in different runtime tests. The build passed with Vite's known over-500-kB warning. Do not call the default-worker run clean or alter timeout/config files.

- [ ] **Step 4: Implement the native editor in the existing file.** Remove `EditorDate`/`parseEditorDate` and slash help. Use a controlled string initialized from `value ?? ""`, an input ref, and transient empty/invalid input state scoped by the existing ProjectId/milestoneId/field keys. Keep the canonical-prop synchronization effect and cleanup reporter. The input must be mutable and enabled. Read `event.currentTarget.value` as a string, validate a nonempty value with `parseDateOnly`, and call `onValidValue(parsed)` only when non-null. Any empty native `input` or `change` event must never call `onValidValue` and must show unapplied feedback and retain the Publish guard; opening/cancelling a picker without an edit event leaves an initially null editor unguarded. Explicit Clear resets the local input immediately, but the guard clears only when canonical props reflect `null` (or were already `null`).

```tsx
const inputRef = React.useRef<HTMLInputElement>(null);
const canonicalText = value ?? "";
const [text, setText] = React.useState(canonicalText);
const [badEmptyInput, setBadEmptyInput] = React.useState(false);
const unapplied = badEmptyInput || text !== canonicalText;
const invalid = badEmptyInput || (text !== "" && parseDateOnly(text) === null);
const error = invalid
  ? "Date not applied. Choose a valid date or use Clear."
  : unapplied ? "Date not applied. The last accepted value is unchanged." : null;
const editorKey = JSON.stringify([projectId, milestoneId, field]);
React.useEffect(() => {
  setText(canonicalText);
  setBadEmptyInput(false);
}, [projectId, milestoneId, field, value]);
const openCalendar = (): void => {
  const input = inputRef.current;
  if (input === null) return;
  if (typeof input.showPicker === "function") {
    try { input.showPicker(); return; } catch { input.focus(); return; }
  }
  input.focus();
};
const recordNativeInput = (input: HTMLInputElement): void => {
  if (input.value === "") {
    setText("");
    setBadEmptyInput(true);
  }
};
const acceptNativeValue = (input: HTMLInputElement): void => {
  const next = input.value;
  if (next === "") {
    recordNativeInput(input);
    return;
  }
  setText(next);
  setBadEmptyInput(false);
  const parsed = parseDateOnly(next);
  if (parsed !== null) onValidValue(parsed);
};
```

Wire `onInput={(event) => recordNativeInput(event.currentTarget)}` to capture sanitized-empty keyboard edits and `onChange={(event) => acceptNativeValue(event.currentTarget)}` to commit valid selections. Ensure a single valid selection produces one callback if both native events fire; only the `change` path may commit. Avoid treating a rerender from an unrelated applicability edit as acceptance. Use `aria-describedby` to associate the visible error and a context element with the input; `aria-invalid={unapplied}`. Include the same Project, occurrence ID, and field context in the input, Open calendar, and Clear accessible names, and connect the error to its input, e.g. `Plan for Kickoff occurrence draft-kickoff in Project workspace-project`, `Open calendar for Plan for Kickoff occurrence draft-kickoff in Project workspace-project`, and `Clear Plan for Kickoff occurrence draft-kickoff in Project workspace-project`; the same definition on two rows must remain distinguishable. Clear's own click calls `onValidValue(null)` and sets local text to `""` and `badEmptyInput` to `false`; it is the sole null-dispatch path. Retain the parent guard text `Correct or clear unapplied dates before publishing.` and both Publish disabled checks.
